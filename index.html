02Details

The three hub-and-spoke repos are public rebuilds of designs I run at work, written from scratch so they can be shared. Each one has CI that runs terraform validate, tflint, Trivy and Gitleaks on every push.

Detail AAWS

aws-hub-spoke-terraform

Spoke VPCs have no internet gateway. Everything leaves through Transit Gateway to a hub with Network Firewall (domain allowlist) and NAT, and replies come back through the firewall too.

  • Two TGW route tables so spoke-to-spoke traffic is inspected as well
  • Private EKS, IRSA scoped to a single service account, SSM-only admin host
  • GitHub Actions deploys via OIDC; PR plans use a read-only role

Terraform · Transit Gateway · Network Firewall · EKS · IRSA

github.com/Tushar-ops23/aws-hub-spoke-terraform →

Detail BAzure

azure-hub-spoke-terraform

Each spoke's subnet has one route, 0.0.0.0/0 to the firewall's private IP, and AKS runs with userDefinedRouting so it never gets its own way out.

  • Private AKS with local accounts disabled, Entra ID RBAC, CNI overlay + Cilium
  • Workload identity and Key Vault over private endpoint, secrets mounted by CSI
  • Privatelink DNS zones hosted once in the hub, linked from every spoke

Terraform · Azure Firewall · AKS · Key Vault · workload identity

github.com/Tushar-ops23/azure-hub-spoke-terraform →

Detail CGCP

gcp-hub-spoke-terraform

Apigee X is the front door, and the only link to the spokes is Private Service Connect. No peering, so spoke ranges can even overlap.

  • External ALB → PSC NEG → Apigee, with Cloud Armor WAF and rate limits; no proxy VMs
  • Private GKE with the DNS-based control plane endpoint, so no bastion
  • Deny-by-default egress policy; Google APIs through private.googleapis.com

Terraform · Apigee X · Private Service Connect · GKE · Cloud Armor

Detail EInternal tool

Deployment failure RCA agent

An agent built on Claude that reads CloudWatch logs when an ECS/Fargate deployment fails, works out the root cause, and posts a plain-English explanation and suggested fix to the team from CodePipeline. Fixes only run after a human approves them, under a narrowly scoped IAM role, with every action written to an audit table in RDS. Average time to resolve a failed deployment went from about 45 minutes to under 10.

AWS ECS/Fargate · CloudWatch · CodePipeline · RDS · Claude

Built at work; not public.
